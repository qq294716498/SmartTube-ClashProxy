# 代理审查与电视交互验收

## 本轮实现

- 将“核心端口已开启”和“订阅、节点、应用出口已配置”分开。首页不再仅凭核心运行就显示代理已开启。
- 启动阶段采用拒绝规则；载入订阅时先将全局组设为拒绝，恢复节点成功后才进入可用状态。
- 配置应用与节点切换防重入。关闭代理会使旧请求回调失效，防止关闭后被自动重新开启。
- 配置应用保留旧文件和全局组选项快照；载入或节点恢复失败尝试回滚。核心调用超时有明确错误，未知状态要求重启。
- 订阅下载先直连，已存在可用代理时可通过本地代理重试。支持 HTTP、HTTPS 及有次数限制的跨协议重定向。
- 同一订阅更新防重入；独立临时文件；跨电视/手机管理实例共用元数据锁。更新完成前再次检查订阅是否被删除或改址。
- 对 YAML 使用安全解析器，并在核心执行前限定本地端口、关闭 TUN 和外部控制器。应用采用全局代理，不执行订阅分流规则。远程 provider 缓存按来源区分。
- 安装进程级动态代理选择器；播放器使用随开关变化的 HTTP 代理请求工厂，避免 Cronet 或旧工厂绕过代理。切换后清理媒体与 API 客户端旧连接。
- 全屏双栏代理中心：固定状态与开关、实时延迟结果、停止测速、排序、选中节点测试、确认成功后显示实际节点、独立连通检测。
- 手机扫码管理显示异步操作结果，不再提前报告成功；局域网管理入口 15 分钟到期。
- 诊断输出隐藏 URL 与常见凭据；YouTube 检测要求 204，不将 404 或 403 误报为通过。

## 自动检查

本地通过 JDK 17 编译器以 Java 8 语法解析全部检出的 Java 文件，未执行 Android 类型检查。脱敏工具的 URL、token、密码、状态码、空值和长度限制已通过 JVM 断言。

工作流新增代理配置策略和错误脱敏单元测试。完整 Android 编译、Lint、JUnit 结果以本轮 GitHub 工作流为准，不能用旧版本的工作流结果代替。

## 必须在设备验收

1. 首次安装：不开启外部 VPN，扫码导入 HTTP 与 HTTPS 订阅；失败应有具体原因且界面可退出。
2. 开启代理：待状态变为已开启，首页推荐、搜索、登录、缩略图、字幕及真实视频均测试；包括 DASH、HLS、SABR（内容可用时）。
3. 播放中切换节点：观察短暂重连，确认新连接通过新节点；不能用延迟测试代替实际播放。
4. 连续开关：启动中关闭、配置中关闭，等待后台结束后必须仍保持关闭。关闭代表允许本软件直连，不是断网开关。
5. 测试全部节点并移动焦点：结果原地刷新，不抢焦点。停止后不再添加结果；换订阅后旧结果不能覆盖新列表。
6. 订阅下载失败、无节点、节点改名、provider 暂不可用时，错误必须可见。不可承诺自动组必然适合当地网络。
7. 电视遥控器完整遍历侧栏、按钮、列表、添加/删除确认、扫码弹窗；返回后主页仍能操作。
8. 杀进程重开及网络断开恢复；确认曾启用的代理自动恢复，错误状态不会伪装成已连通。

## 边界

本软件的代理不是系统 VPN，不代理其他应用。外部浏览器、电视系统组件及第三方登录页面的独立进程不属于进程级 HTTP 代理覆盖范围。视频可用性、地区限制与带宽还取决于订阅节点及网络，不能保证“所有视频永远可用”。本轮没有实体电视、手机或远端真实视频的运行验证证据。
